# hw6
# Ozon: подсказка категории товара при создании карточки

Учебная работа: BPMN + C4 (Context, Containers, Components) для одного ML-процесса.

## 1. Компания, процесс, границы
**Компания:** Ozon.
**Процесс:** продавец создаёт карточку товара; система предлагает категорию по названию, описанию и фото; продавец подтверждает или меняет её; карточка с выбранной категорией уходит на модерацию.
**Конкретный результат:** карточка с выбранной категорией, отправленная на модерацию.
**Входит в схемы:** путь от начала создания карточки до отправки на модерацию, запасной путь (недоступность модели, низкая уверенность), возврат разметки в обучение.
**Сознательно за рамками:** заполнение атрибутов и цены, внутреннее устройство модерации (показана как внешняя система), уровень Code.

## 2. Задача модели
Многоклассовая классификация по листьям дерева категорий.
- **Вход:** название, описание, эмбеддинг фото, признаки продавца (история выбранных категорий).
- **Выход:** топ-3 категории с вероятностями p1 ≥ p2 ≥ p3 и версия модели.
- **Бизнес-результат:** меньше ошибочных категорий, быстрее создание карточки, меньше ручных исправлений модерацией.

## 3. Кто получает результат
- Продавец: предзаполненная категория или топ-3 в форме.
- Система модерации каталога: карточка с итоговой категорией.

## 4. Пороги и запасной путь
Пороги и тайм-аут применяет **Card Service**, а не модель.

| Условие | Что делает процесс |
|---|---|
| Нет ответа модели за 300 мс или Category Suggest Service недоступен | запасной путь: поиск по дереву категорий в Category Search (правило), выбирает продавец |
| p1 ≥ 0.85 | категория предзаполняется, продавец подтверждает или меняет  |
| 0.50 ≤ p1 < 0.85 | показываются топ-3, продавец выбирает |
| p1 < 0.50 | запасной путь, как при недоступности |

## 5. Обратная связь для обучения и оценка качества
- Выбор продавца (событие `CategoryChosen` с версией модели и p1) — слабая метка.
- Исправление модерации (событие `ModerationOutcome`) — сильная метка; при конфликте приоритетна она.
- Переобучение, оценка на отложенной выборке и публикация версии: (Training Pipeline → Model Registry).
- Онлайн-метрики: доля принятых подсказок и top-1 accuracy по версиям (champion против canary).

## 6. Допущения
1. Модель — текстово-визуальный классификатор; реальная архитектура Ozon неизвестна.
2. Пороги 0.85 и 0.50 и тайм-аут 300 мс выбраны мной.
3. Есть canary-выкатка новой версии на 5% трафика.
4. Стек (Go, FastAPI, Redis, Kafka, MLflow, Airflow, PyTorch, Elasticsearch, PostgreSQL) выбран мной.
5. Модерация публикует исход проверки в шину событий.
6. Признаки продавца (история категорий) лежат в онлайн-хранилище признаков.
7. Переобучение идёт по расписанию, а не по триггеру.
8. Запасной путь — поиск по ключевым словам по дереву категорий, а не откат на прошлую версию модели.
9. Пороги применяются в бизнес-сервисе, а не внутри модели.

## 7. Источники и что придумано
Опирался на наблюдение за интерфейсом кабинета продавца Ozon и общие знания о построении ML-систем. Готовых схем и чужих репозиториев не использовал. **Все схемы, пороги, контейнеры, потоки данных и допущения из раздела 6 придуманы мной.**
